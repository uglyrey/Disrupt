# Знакомство и «Что beresta знает обо мне» на сайте v1

Ветка `feature/claude-profile-web-v1`, от `feature/claude-reminder-time-v2` (6812932). Здесь только сайт. Бэкенд, миграция и тексты вопросов делает Агент K, они описаны в `docs/profile-v1.md`.

API из контракта в этой ветке ещё нет. Код написан по контракту, тесты и снимки экрана идут на подмене.

## Что есть

- `app/static/profile.js` и `profile.css`: всплывающая форма «Знакомство» и диалог «Что beresta знает обо мне».
- Пункт «Что beresta знает обо мне» в меню. На десктопе его добавляет `profile.js` в `#nav-menu .nav-bottom` (кнопка `#open-profile`). На телефоне он стоит в общем меню в `index.html` (`data-proxy="open-profile"`) и нажимает ту же кнопку.
- Кнопка «В Google Календарь» в списке напоминаний заметки (`reminders.js`).
- Тесты `tests/web_profile.cjs`, подключены из `web_structure.cjs`.

## Когда всплывает форма

Условие одно. `GET /api/v1/auth/me` вернул `profile_state === "new"`. Для других состояний (`declined`, `pending`, `ready`, `failed`) форма не показывается и лишнего запроса нет. Если сервер поля не знает, форма тоже не показывается.

`app.js` зовёт `BerestaProfile.start(user, api)` после каждого входа, рядом с часовым поясом. Дальше `profile.js` читает `GET /api/v1/profile`, берёт вопросы, вступление и строку про данные и ждёт спокойного момента. Форма не появляется, пока:

- не закрыт баннер новой политики (`#policy-banner`);
- виден выбор cookie (`#cookie-consent`);
- открыт любой другой `dialog` или всплывашка инструментов заметки (`body.has-pop`);
- на экране подсказка тура (`.guide-bubble`).

Проверка идёт сразу и потом раз в секунду. Для нового человека это сразу после входа, для существующего при ближайшей загрузке страницы. За одну загрузку страницы форма показывается один раз. Если её закрыли на втором шаге или позже, она вернётся при следующей загрузке, ответы при этом сохранены.

Подсказки тура (`guide.js`) ждут, пока форма открыта или вот-вот откроется (`BerestaProfile.pending()`), и стартуют после неё. Форма в свою очередь ждёт уже идущий тур.

## Шаги

1. Вступление. «Давайте познакомимся», тёплый текст (`intro` из API, запасной текст зашит), строка про данные (`privacy` из API, запасная строка зашита и совпадает с решением владельца). Кнопки «Начать» и «Нет, спасибо».
2. Вопросы, по одному на шаг. Поле до 1000 знаков, счётчик «Осталось знаков N» от 800. Кнопки «Назад», «Пропустить», «Далее», ход «3 из 7». Число вопросов и их текст приходят из API.
3. Последний шаг. Радио «Только Telegram» (по умолчанию, берётся из `reminder_channel` аккаунта), «Telegram и Google Календарь», «Только Google Календарь» и пояснение про кнопку календаря и отсутствие доступа к аккаунту Google. Кнопка «Готово».
4. Последний экран «Спасибо! beresta разбирает ответы, это займёт до минуты.» и кнопка «Закрыть».

«Нет, спасибо» сразу шлёт `POST /api/v1/profile/decline` и закрывает форму. Esc и крестик на вступлении тоже означают отказ, но сначала в самой форме появляется строка «Больше не показывать?» с кнопками «Да» и «Вернуться». Браузерный `confirm()` не используется. Esc и крестик на любом другом шаге просто закрывают форму без отказа.

«Готово» шлёт `POST /api/v1/profile/answers` с `{answers: {qid: текст}, reminder_channel}`. В ответах только непустые, обрезанные по краям тексты, не длиннее 1000 знаков. Если ответов нет совсем, запрос не уходит. Форма объясняет, что нужен хотя бы один ответ, и предлагает «Вернуться к вопросам» или «Нет, спасибо». Ошибка сервера (например, лимит ИИ) показывается в форме, ответы остаются.

«Пропустить» стирает ответ на этом шаге и идёт дальше. «Далее» с пустым полем просто идёт дальше.

## Ответы до отправки

Ответы лежат в памяти страницы и в ключе `beresta.profile.draft.v1`: `{"answers": {...}, "channel": ...}`. Запись идёт через `window.berestaConsent.write`, то есть в `sessionStorage`, а в `localStorage` только после «Принять все». Ключ добавлен в `OPTIONAL_KEYS` в `cookie-consent.js`, при отказе от необязательного хранилища он чистится. После успешной отправки и после отказа значение очищается. Если хранилище закрыто, форма работает на памяти страницы.

Голосовой ввод в форму не добавлен. Запись голоса в `app.js` завязана на форму захвата (поток, подтверждение, загрузка файла), простого повторного использования нет.

## «Что beresta знает обо мне»

Диалог `#knowledge-dialog`. При открытии читает `GET /api/v1/profile`.

| Состояние | Что видно |
| --- | --- |
| `ready` | список выводов. У каждого «Изменить» (поле прямо в строке, «Сохранить», «Отмена», `PATCH /profile/facts/{id}`) и «Удалить» (`DELETE`). Ниже «Пройти вопросы заново» и «Удалить всё» |
| `pending` | «Разбираем ответы…», опрос `GET /profile` каждые 3 секунды, не дольше 2 минут |
| `pending` дольше 2 минут | «Разбор занимает дольше обычного», кнопка «Проверить» |
| `failed` | «Не получилось разобрать ответы», кнопка «Попробовать ещё раз» (`POST /profile/retry`), дальше опрос как в `pending` |
| `declined`, `new` | короткий текст и кнопка «Пройти вопросы» |

«Удалить всё» спрашивает внутри диалога («Да, удалить всё» и «Отмена»), потом `DELETE /api/v1/profile`, диалог показывает вид `declined`, форма «Знакомство» сама не возвращается. «Пройти вопросы заново» закрывает диалог и открывает форму, поля заполнены прошлыми ответами из `answers` (если нет черновика). Закрытие такой формы Esc или крестиком на вступлении ничего не отклоняет.

Опрос останавливается, когда состояние перестало быть `pending`, когда прошли 2 минуты и когда диалог закрыт. Сменить канал можно в любом состоянии, это радио под списком: `PATCH /profile/reminder-channel` сразу при выборе, при ошибке прежний выбор возвращается. Внизу строка про данные.

Для проверок можно менять окна `window.profileWaitMs` (проверка тихого момента, 1000), `window.profilePollMs` (3000) и `window.profilePollMaxMs` (120000).

## Кнопка «В Google Календарь»

Если у напоминания в списке есть `calendar_url`, в строке действий появляется ссылка «В Google Календарь» (`a.button-link.small.calendar-link`, `target="_blank"`, `rel="noopener noreferrer"`, скрытая подпись «откроется в новой вкладке»). Ссылка рисуется только для `https://calendar.google.com/...` и `https://www.google.com/...`. Любой другой адрес (включая `javascript:` и `http:`) отбрасывается. Без поля ничего не меняется. Список напоминаний в заметке единственное место, где сайт показывает напоминания по строкам, поэтому кнопка только там.

## Безопасность и доступность

- Всё строится через DOM и `textContent`. `innerHTML`, `style=` и инлайн-скриптов нет, CSP не менялся.
- Форма и диалог это `<dialog>` с `showModal()`. Фокус держит сам браузер, плюс запасная ловушка Tab. Фокус при открытии на поле, на безопасной кнопке или на заголовке.
- `<progress>` для хода, `role="alert"` для сообщения про пустую форму, `role="status"` для строки состояния.
- На телефоне (до 640 px) форма и диалог занимают весь экран, кнопки действий липнут к низу.
- Стили кнопок только из `buttons.css` (`.primary`, `.secondary`, `.quiet`, `.danger`, `.small`, `.large`, `a.button-link`).

## Решения, принятые без владельца

- Голос в форме не делаем.
- Форма показывается один раз за загрузку страницы, закрытие не на вступлении откладывает её до следующей загрузки.
- «Пропустить» стирает ответ шага.
- Адрес календаря проверяется по списку хостов Google.
- Для `reminder_channel` форма берёт значение из `auth/me`, дальше из `GET /profile`.
- Прогресс на шаге с каналом подписан «Последний шаг», а не «8 из 7».
