# Модель и бюджет пилота

Выбрана `claude-opus-4.7`. Модель есть в каталоге нашего ключа. Тариф шлюза на 12 октября 2026 года составляет 854 ₽ за миллион входных токенов и 4270 ₽ за миллион выходных. Пример с 1000 входных и 500 выходных токенов стоит 2,99 ₽ без скидки за кэш. Это расчёт по тарифу, не измерение средней заметки. Шлюз не называет валюту, владелец подтвердил рубли.

Opus дороже DeepSeek Pro и Flash. Его выбрали для качества анализа текста и помощника, а не для максимального числа дешёвых запросов. Проверены каталог, тариф и формат запросов на подменённом HTTP. Платная генерация агентом не выполнялась. Качество и задержку новой модели нужно оценить на пользовательских записях.

С Opus убрана `temperature`, поскольку модель отклоняет её. Ответ запрашивается через `json_schema`. Ограничения длины и проверка цитат остаются в приложении. Документация [Anthropic](https://platform.claude.com/docs/en/models/opus-4-7/overview) и [LiteLLM](https://docs.litellm.ai/docs/providers/anthropic).

## Лимиты

Каждый пользователь, включая новый аккаунт, получает 100 единиц в календарные сутки по Москве. Текст и запрос помощнику стоят одну единицу, голос две плюс одну за каждую полную минуту. Ручное сохранение бесплатно. Пределы вызовов за всё время увеличены до 100000 на ключ и на пользователя, чтобы прежний потолок 100 не мешал дневной квоте. Эти счётчики не обнуляются.

На ключе 75000 ₽. На следующие этапы оставлен резерв 25000 ₽. Перед отправкой проверяется остаток, который вернул шлюз. Для недавних, неопределённых и ещё не учтённых вызовов временно резервируется по 250 ₽. Это защитный запас, не цена заметки и не списание. Формат входа ограничен 12000 символами, выход до 4000 токенов. Нужно пересмотреть запас при изменении тарифов или размеров контекста.

При достижении денежного резерва новые обращения приостанавливаются. Исходники и очередь сохраняются. Неизвестные платные попытки автоматически не повторяются. Если сведения о балансе старше 15 минут или отсутствуют, новые обращения тоже приостанавливаются. После успешного обновления баланса worker продолжает работу без ручного запуска.

## Учёт

`beresta-budget.timer` обновляет сведения каждые пять минут через `GET /key/info`. Запрашивается только наш ключ. Ключ передаётся в заголовке, не в URL. Ответ сохраняется по разрешённым полям без ключа, токена и чужих данных.

Админка показывает бюджет всего ключа за всё время, расход, остаток, резерв, доступную сумму пилота и время проверки. Фильтры дат на этот блок не влияют. Сюда входят тестовые аккаунты, STT и другие приложения, если они используют тот же ключ. Расходы по отдельным операциям и выбранному периоду остаются отдельными метриками. Неизвестные старые списания не заменяются расчётом по нынешнему тарифу.

API и worker читают `data/billing/current.json` через отдельный том только для чтения. API не получает ключ модели. Таймер установлен только на ядре. Сервер бота не получает ключ, баланс, базу или аудио.

Настройки production

```env
NOTES_CLOUDRU_MODEL=claude-opus-4.7
NOTES_DAILY_UNIT_LIMIT=100
NOTES_NEW_ACCOUNT_UNIT_LIMIT=100
NOTES_LIVE_CALL_LIMIT=100000
NOTES_LIVE_USER_CALL_LIMIT=100000
NOTES_GATEWAY_BUDGET_FILE=/app/data/billing/current.json
NOTES_BUDGET_RESERVE_RUB=25000
NOTES_BUDGET_ATTEMPT_RESERVE_RUB=250
```

Для установки создать `data/billing` с владельцем 1000 и правами 0700, установить service и timer из `deploy/ops`, запустить первое обновление и лишь затем включить проверку баланса. Не обнулять файл при ошибке обновления. Штатное резервирование и его исправление из PR #46 должны сохраняться в следующих сборках.
