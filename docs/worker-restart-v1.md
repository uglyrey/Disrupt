# Восстановление обработчика после перезагрузки

23 октября 2026 года VPS перезагрузился. При остановке PostgreSQL worker получил
OperationalError и завершился с кодом 1. Политика restart: no оставила его
выключенным. Сайт и бот работали, но три записи ждали в очереди.

После запуска того же контейнера все три задания успешно завершились.
Новых проверочных запросов к модели не создавали. Содержимое записей не читали.

В production для worker задан restart: unless-stopped. Уже включённый владельцем
контейнер восстанавливается после аварии процесса и перезагрузки Docker.
Первое включение остаётся через профиль owner-live. Настройки разрешения реального
провайдера, лимиты и защита бюджета не меняются.

Для намеренной остановки используйте beresta-core stop worker. Явно остановленный
контейнер не запускается после перезагрузки Docker. Резервирование по-прежнему
останавливает писателей и возвращает только ранее работавшие контейнеры.

На действующем VPS политика применена командой docker update --restart
unless-stopped к существующему worker. Пересборка образа и повтор заданий
не нужны. После следующего создания контейнера правило возьмётся из Compose.

Проверены состояние контейнера, политика Docker, production Compose и отсутствие
ожидающих заданий. Повторную перезагрузку VPS и платные тестовые обращения
к модели не выполняли. Проверка /health подтверждает API, но не работающий worker.
