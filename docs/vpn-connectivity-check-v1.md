# Временная проверка VPN

30 октября 2026 запущена отдельная статическая страница на Хельсинки.

Адрес `https://beresta-netcheck-20261030.185-106-94-251.sslip.io/`.
Автоматическое отключение 30 октября в 15:05 по Москве. После этого ссылка не работает.

Страница сравнивается с `https://app.berestaapp.ru` при включённом VPN.
Отличаются и DNS, и IP сервера. Один этот тест не разделяет влияние двух факторов.
Главное наблюдение даёт одновременная проверка обоих адресов во время сбоя.

Входа, заметок и аналитики здесь нет. Обратного прокси в ядро нет.
Версия 3 предлагает открыть основной сайт в обычной новой вкладке и вручную
выбрать результат. Автоматических межсайтовых запросов больше нет.
Отчёт остаётся в браузере, пользователь сам передаёт его владельцу.
Варианты 1 и 2 с fetch к /health и favicon.svg дали ошибку также при доступном
основном сайте. Они ненадёжны, их результаты не подтверждают отказ DNS.

## Изоляция

- Отдельный Caddy 2.10.2 под nobody, административный API выключен.
- Бинарный файл взят из уже работающего контейнера Caddy российского VPS.
  SHA256 `4ef1f68c70219536b2711fd16547a79841a2dec2d6b4e56b1e3e5e9da76028e6`.
- Временный исполняемый файл `/opt/beresta-netcheck-caddy`, остальное в `/run/beresta-vpn-netcheck`.
- Входящие 80 и 443 разрешены только временными правилами iptables с отдельной меткой.
  Постоянные правила UFW не меняются. Контейнеры и правила Docker не меняются.
- Ограничения 128 МБ RAM, 25% CPU и 64 процесса. Журнал доступа выключен.
- RuntimeMaxSec и отдельный таймер ограничивают работу двумя часами.
  ExecStopPost удаляет правила, временные файлы и исполняемый файл.
- Свои сертификат и ACME-ключ временного имени остаются только на Хельсинки
  и удаляются вместе с временным каталогом. Ключи приложения не используются.

## Проверено

Caddy validate, Ruff, синтаксис JavaScript, HTTPS с проверкой сертификата,
200 для /health и 404 для /admin и /internal. Внешняя проверка с российского VPS
и через существующий SOCKS прошла. Пробный systemd-откат подтвердил исходные
iptables, неизменность UFW и отсутствие перезапусков бота и резервного ИИ.

Обычный сетевой путь ПК давал тайм-аут и к временному адресу.
Встроенный браузер открыл страницу, но прямой переход к ресурсу Beresta
завершился тайм-аутом. Владелец подтвердил открытие контрольной страницы
при недоступном основном сайте. Затем основной сайт снова открылся,
но автоматическая проверка версии 2 по-прежнему дала ошибку. В то же время
пять обычных запросов с ПК к favicon.svg получили 200. Автопроверка удалена.
Причина VPN-сбоев и пригодность такой схемы для постоянного входа не установлены.

Ручное досрочное завершение `systemctl stop beresta-vpn-netcheck.service`.
Результат отката находится в `/run/beresta-vpn-netcheck-cleanup.json`.
DNS проекта, приложение, база, бэкапы и конфигурация VPN не менялись.

## Контроль на том же российском IP

Для следующего теста добавлен адрес
`https://beresta-netcheck-20261030.178-217-98-101.sslip.io/`.
IP остаётся `178.217.98.101`, меняются доменное имя и DNS-сервис.
Проверять надо вместе с `https://app.berestaapp.ru` на одном устройстве,
с одним VPN и в тот же момент. Автоматических запросов браузера здесь нет.

Это отдельный статический маршрут существующего Caddy. Он не проксирует
запросы в приложение. Никаких аккаунтов, cookie приложения и содержимого заметок
по этому имени нет. Для остальных путей, включая /admin, /internal и /api, ответ 404.

Изменение внесено через локальный API внутри сетевого пространства Caddy.
API наружу не открывался. Маршрут имеет собственный @id, изменения защищены If-Match.
Файл рабочего Caddy, Compose, DNS Beresta и firewall не менялись.
Контейнеры не перезапускались. HTTPS и запреты маршрутов проверены из Хельсинки.
Первые TLS-проверки пришлись на выпуск сертификата, после его завершения прошли.

Перед установкой verify_route.py проверил вставку и удаление маршрута
в одноразовом Caddy с network=none. Основной hostname в тесте не изменился,
служебные пути закрыты, после удаления исходная конфигурация совпала по хэшу.
Первый запуск проверки опередил запуск контейнера, повтор с ожиданием готовности прошёл.

Таймер удалит российский маршрут 30 октября в 14:38 по Москве.
Удаляется только его @id и сертификаты этого тестового имени.
Другие изменения Caddy при откате не перезаписываются.
Досрочное удаление `python3 /run/beresta-vpn-russia-check/russia_check.py rollback`.
Отчёт отката `/run/beresta-vpn-russia-check-result.json`.
Фактический откат российского маршрута пока ожидается; изолированный тест не заменяет его проверку.
