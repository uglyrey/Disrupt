# Проверка совместимости часовых поясов

Отдельная сборка `integration/timezone-privacy-release-v1` подготовлена от серверного `6c0fc6c`. В неё включён `cb9776b` из `feature/claude-timezone-v1`. После проверки совместимости владелец разрешил установку. На обоих VPS установлен `c5ce9c02647dd8df8de5921a7995cd562603ffef`.

Конфликты разобраны вручную. В `deliveries.py` сохранены учёт компонентов и новый доступ к поясу пользователя. В `index.html` оставлены оба уведомления, подключение почты и смена часового пояса.

Миграция `f8c3d1a5b902` соединяет `c2e4a6b8d0f1` и `e1a4c7f2b9d3`. Она не меняет данные. Новые поля пояса добавляет миграция коллеги. У старых пользователей пояс остаётся пустым до определения или выбора.

Сохранены почта и согласие на рассылку, картинки при создании заметки, импорт документов, метрики, поиск, дайджесты, навигация «Назад», бюджеты и резервный ИИ. Сообщение о конфиденциальности остаётся на главном экране.

Добавлена проверка перехода с текущей миграции `c2e4a6b8d0f1`. Она проверяет сохранение связей картинки, её байтов и почтового согласия на заполненной тестовой базе. Публичный контракт заново сгенерирован для общей сборки.

Зависимости и Compose не изменены. Ядро и бот собраны на текущих проверенных runtime. Миграция `f8c3d1a5b902` выполнена. CI установленного коммита зелёный, включая 1880 Python-тестов с PostgreSQL, веб, образы, резервирование и восстановление. Выбор, поиск и сохранение пояса проверены в Edge на mock при ширинах 360, 390 и 1280 px. Реальные запросы ИИ для проверки не отправлялись.

Перед установкой сделана согласованная копия `beresta-20261014T163139-dc978618.tar.age`. Она скачана на ПК, SHA-256 совпал с `5fa450e775286bbcc2e5154c30207b08069422e5465adea324fae3451b907434`. Изолированное восстановление проверило 34 оригинала аудио, база сохранила три картинки. Новые миграции на восстановленной копии прошли, `alembic check` не нашёл расхождений. Приложения и Telegram там не запускались, тестовая БД остановлена.

После установки проверены HTTPS, файлы интерфейса, health, один worker и один бот. Контейнер бота достигает ядра. Внутренний API без секрета даёт 401, правильный секрет проходит авторизацию нового маршрута. Публичные `/internal`, `/admin`, `/docs` и `/openapi.json` дают 404. API опубликован только на `10.77.0.1:18000`, у PostgreSQL публикаций нет. С Хельсинки публичные 18000 и 5432 недоступны; с ПК ответа HTTP и PostgreSQL на них не получено. Правила Docker и служба firewall сохранены.

При установке бота исправлено имя файла окружения. Теперь используется штатный `beresta-bot`, который читает `.env.bot`. Межсерверный SSH во время установки обрывался, поэтому установка завершена с ПК. После неё Docker-контекст координатора снова успешно читает состояние бота.

Восстановление по почте проверено для согласованного аккаунта без чтения пароля и ссылки. Почта подтверждена, приложение создаёт запрос. SMTP.BZ отмечает письмо как `sent`, получатель подтвердил доставку нового письма. Ошибка отправки не воспроизвелась, доступ к корпоративному ящику не понадобился. Саму смену пароля подтверждает владелец.
