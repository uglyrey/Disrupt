# PurpleAPI как подготовленный резерв Beresta

Решение владельца от 12 октября 2026: использовать PurpleAPI с `gpt-6.1-sol`, но автоматическое переключение пока оставить выключенным до проверки тарифа. На сервере Хельсинки посредник может работать и отвечать на `/health`; это не вызывает модель. На ядре `NOTES_FALLBACK_ENABLED=false` и нет флага `/etc/beresta/ai-failover`.

В кабинете PurpleAPI показан базовый адрес `https://purpleapi.lol/v1`, модель `gpt-6.1-sol` с коэффициентом `x3` и баланс в токенах. Публичной денежной цены для этой покупки не видно. Имеющийся учёт Beresta `fallback_spend` считает приблизительные доллары по тарифу прямого OpenAI, поэтому его предел `$10/день` нельзя считать пределом расходов PurpleAPI. Не включать резерв до подтверждения правил списания и настройки подходящего ограничения.

PurpleAPI показывает в каталоге 41 модель, но не показывает `whisper-1` или иную модель распознавания речи. Настройка `AI_RELAY_STT_MODELS=` закрывает аудиомаршрут посредника, `NOTES_FALLBACK_STT_MODEL=` запрещает ядру отправлять туда аудио. Текстовые заметки можно будет переключить на резерв после отдельного решения; для новой голосовой заметки при недоступном основном STT полноценного резерва пока нет.

Посредник разрешает только фиксированные адреса `api.openai.com` и `purpleapi.lol`, выбираемые `AI_RELAY_PROVIDER`; URL из запросов клиента не принимаются. Для `gpt-6.1-sol` он проверяет потолок `max_tokens`, затем передаёт `max_completion_tokens` и убирает `temperature`. Совместимость с реальным ответом PurpleAPI не проверена: платных запросов к модели агент не делал. В инструкции PurpleAPI предложен загрузчик стороннего скрипта для приложения ChatGPT; для серверной настройки он не нужен и не запускался.

## Хельсинки

Секрет `secrets/ai_provider_api_key.txt` хранится только на этом сервере с владельцем UID/GID 1000:1000 и правами `0400`. Ключ никогда не помещать в `.env.production`, аргументы команд, Git или отчёт. В `.env.production`:

```env
AI_RELAY_PROVIDER=purpleapi
AI_RELAY_API_KEY_HOST_FILE=../secrets/ai_provider_api_key.txt
AI_RELAY_CHAT_MODELS=gpt-6.1-sol
AI_RELAY_STT_MODELS=
```

После создания секрета: `beresta-bot --profile ai-relay up -d --build ai-relay`. Проверять с ядра только `curl http://10.77.0.2:18100/health` и `401` без токена на POST. Публичный порт `18100` должен оставаться закрытым. Штатный бот и его том не пересоздавать ради этой настройки.

## Ядро

Настройки для будущего включения: `NOTES_FALLBACK_BASE_URL=http://10.77.0.2:18100/v1`, `NOTES_FALLBACK_MODEL=gpt-6.1-sol`, `NOTES_FALLBACK_STT_MODEL=`. Пока оставить `NOTES_FALLBACK_ENABLED=false`; файл-флаг `/etc/beresta/ai-failover` не создавать. Токен посредника уже лежит в секрете на ядре, но без флага не монтируется в worker.

Перед включением уточнить у PurpleAPI цену и списание токенов, обеспечить корректный лимит, проверить договор и обработку пользовательских данных третьей стороной. Первый настоящий текстовый запрос и смысл результата проверяет владелец; агент не отправляет тесты к модели.
