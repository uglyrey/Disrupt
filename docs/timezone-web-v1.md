# Часовой пояс в вебе

Ветка `feature/claude-timezone-web-v1`. Сервер описан в `docs/timezone-v1.md` (Agent T). Здесь только веб. Контракт API общий: `GET /api/v1/timezones`, `GET` и `PATCH /api/v1/account/timezone`, поле `timezone` в `/api/v1/auth/me`.

## Что делает веб

Всё в `app/static/timezone.js` (`window.BerestaTimezone`). `app.js` после каждого входа вызывает `BerestaTimezone.start(user, api)`.

- Автоопределение. Если `auth/me` вернул `timezone: null`, а браузер знает пояс (`Intl.DateTimeFormat().resolvedOptions().timeZone`), один раз молча уходит `PATCH {timezone, source: "auto"}`. Если пояса нет или он не распознан, ничего не отправляется, сервер считает по Москве. Геолокация, IP и внешние сервисы не используются. Если поля `timezone` в ответе нет вообще (старый сервер), веб ничего не делает.
- Поездка. Если сохранённый пояс и пояс устройства отличаются по текущему смещению UTC, над рабочей областью появляется строка «Похоже, вы сейчас в другом часовом поясе: Новосибирск (UTC+7). Сменить?». Сравниваются смещения, а не названия, поэтому `Europe/Kiev` и `Europe/Kyiv` не беспокоят. «Сменить» отправляет `source: "manual"`. «Оставить» закрывает строку и запоминает пояс устройства через `berestaConsent` и `sessionStorage` (ключ `beresta.timezoneDismissed`, необязательный, до согласия живёт только во вкладке). Другой пояс устройства спросит снова. Окон и блокировок нет.
- Настройки. Строка «Часовой пояс» в меню слева (на телефоне в общем меню, группа «Ещё») открывает диалог. Он показывает текущий пояс, поиск и список всех поясов из API. Поиск находит по русскому названию, IANA и смещению: `новосиб`, `asia/omsk`, `+7`, `UTC+7`, `+5:30`. Смещение ищется точно, `+5` не покажет `+5:30`. Список отсортирован так, как отдал сервер (по смещению). Стрелки, Home и End двигают фокус по списку, в нём один пункт Tab. Enter в поиске выбирает первый найденный пояс, второй Enter сохраняет. «Сохранить» и «Определить автоматически» шлют `source: "manual"`.
- Форма напоминания (`reminders.js`). Пояс по умолчанию: пояс аккаунта, потом пояс устройства, потом Москва. Прежнее запоминание последнего пояса в браузере убрано. Подсказки поля пояса и названия берутся из того же кэшированного списка. Если список не загрузился, работает короткий встроенный (23 пояса). «(Москва)» в строке напоминания показывается, когда пояс напоминания не совпадает с поясом аккаунта.
- Список `/api/v1/timezones` запрашивается один раз на страницу. После ошибки следующее обращение пробует снова.

## Решения

- Диалог в `index.html` статический, как остальные. Все узлы строятся через DOM, без `innerHTML`, инлайн-стилей и скриптов.
- Сроки задач в `tasks.js` показываются по часам устройства, без пояса. Подпись «по Новосибирску» там была бы неверной, поэтому её нет. В обзоре название пояса ближайшего напоминания теперь берётся из списка.
- Ключ `beresta.reminderZone` больше не пишется. Он остаётся в списке очищаемых ключей и на странице cookie помечен как прежний.

## Проверка

- `tests/web_timezone.cjs` подключён из `tests/web_structure.cjs`. Его можно запустить и отдельно: `node tests/web_timezone.cjs`. Сервер в тестах подменён, живой сервис не вызывается.
- `tests/web_reminders.cjs` теперь загружает `timezone.js` и проверяет, что новая форма начинается с пояса аккаунта, а не с последнего использованного.
