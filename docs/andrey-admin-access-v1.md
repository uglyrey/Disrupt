# Доступ Андрея, 11 октября

Админка остаётся за SSH-туннелем. Подготовленный публичный HTTPS-доступ отменён,
его изменения не устанавливались. С основного домена административные пути дают 404.

На обоих VPS создан отдельный SSH-пользователь `beresta-andrey`.
Разрешён только предоставленный ключ с отпечатком
`SHA256:0vCwybtT7kDLG0b5BKbep4WvvEMA8ls5V6P49x/LDXU`.
В Хельсинки можно открыть только соединение с `10.77.0.1:22`, на ядре только
с `10.77.0.1:18000`. Оболочка, команды, SFTP, PTY, удалённые туннели,
передача SSH-агента и остальные назначения запрещены.

Конфигурация подключена в конце `sshd_config`, прежний файл сохранён.
Перед reload прошли `sshd -t` и сравнение эффективной конфигурации root.
После reload выполнены настоящие команды root на обоих VPS.
Ключ Андрея не даёт доступ к серверным файлам или секретам.

Создан отдельный администратор `andrey`, пароль сгенерирован приватно.
Пароль и TOTP сохранены в `Beresta-owner-secrets/andrey-authenticator.txt`
на ПК Марка. Права только у Марка и SYSTEM. Копия сверена по SHA256,
временный файл на сервере удалён. Общий пароль Марка не используется.

Приватный вход по паролю и TOTP, статистика, CSV, ZIP, журнал и выход
проверены на VPS без вывода секретов. Эти проверки не подтверждают,
что Андрей импортировал ключ в приложение на телефоне или подключился со своего ПК.

Марк передаёт папку `scripts/andrey-admin` и отдельно приватный файл доступа
вне чата с агентом. Приватный SSH-ключ Андрея остаётся только у него.
Инструкция и launcher находятся в этой папке, ключи серверов закреплены.

Для отзыва доступа отключить администратора через `admin_cli disable andrey`
и убрать его ключ из обоих `authorized_keys`. Это не затронет доступ Марка.
